Rules of thumb

  • OT traffic is boringly regular: the same devices, ports, function codes and intervals all day.
  • Normal function codes: FC03 and FC06 only. Normal register range: 0–99. Normal writers: HMI-01, ENG-WS only.
  • Anything new (a host, a port, a function code, a big frame) deserves a look.
  • "Normal" is not always "good": SNMPv2c (clear-text community), LLMNR/NBNS (name poisoning) and SSDP are findings in their own right.

Detection maths (Sections 4.3–4.4)

Baseline (Day 3)

Cut traffic into 5-minute windows → count features per window → mean, std, percentiles.

Z-score (Day 4)

z = (value − mean) / std    flag if |z| > 3
  • std ≈ 0 (feature never changes)? Use a minimum std (otlab uses 1) or every tiny change becomes "infinite".
  • Higher threshold → fewer false alarms but more misses.
  • One global baseline mixes day and night; per-shift baselines are sharper.

Isolation Forest (Day 5)

  • Train on normal windows only; odd windows are isolated in fewer random splits.
  • contamination = share of training data treated as outliers = the alarm threshold.
  • It can't rate something as more unusual than the most unusual training window, so lowering contamination can hide real attacks.

Scoring

TPR = anomalies detected ÷ anomalies planted · FPR = normal windows flagged ÷ normal windows

Wireshark moves worth knowing

  • Profile (bottom-right) → Palanca-OT: OT colours, filter buttons, FC/Register columns.
  • Ctrl+G go to packet number · Ctrl+→ next packet in conversation.
  • Right-click a field → Apply as Filter / Apply as Column.
  • Statistics › Conversations: who talks to whom, how much.
  • Statistics › Protocol Hierarchy: protocol mix.
  • Statistics › I/O Graphs: rate over time (spikes!).
  • Analyze › Expert Information: warnings such as duplicate IP.
  • File › Export Specified Packets: save just the evidence.
  • View › Time Display Format › Seconds Since Beginning of Capture = the times otlab reports.

On the job: capture safely

  • Passive only. Use a SPAN/mirror port or a hardware TAP. Listening can't trip a breaker; sending can.
  • Never scan, ping-sweep, or send Modbus/OPC UA requests to live control equipment without a written, approved work permit. Some PLCs and relays crash on a simple port scan.
  • Get permission from the asset owner and tell the control room before connecting anything.
  • Captures contain plant data and sometimes credentials: store them encrypted and delete them when you're done.
  • A detector's alarm is a question, not a verdict. Confirm in the packets before you escalate, and escalate process-safety concerns immediately.
